## 页面外观

2026-10-30 更新：页面采用左侧信息栏与右侧任务主区的分区布局，占满插件可用宽度，宽屏不再限制为居中 1440px。左侧「接下来」「提醒与回顾」「日历」三块随可用高度伸缩，整体与任务区上下对齐；内容过长可在卡片内滚动，窗口过矮可滚动左栏。输入、搜索、下拉框和按钮统一尺寸与状态，窄屏自动改为单列，任务区优先展示。

顶部「外观」提供三种选择：

| 选项 | 行为 |
|---|---|
| 跟随系统（默认） | 随操作系统的深浅主题实时切换 |
| 浅色 | 固定使用纸白背景与松绿色强调色 |
| 深色 | 固定使用墨绿背景与浅绿色强调色 |

选择保存在当前浏览器中，刷新页面仍然保留。页面、详情弹窗和日期/时间输入使用同一套主题，不改变宿主其他页面的外观。浏览器禁止本地存储时，本次打开期间仍可切换，但无法记住选择。

## 记录

五个域（工作/销售/创作/灵感/助手）形态不同，记法都一样：**说一句话**。

```
下周三之前把方案发给张明
记一条：给客户的产品手册要改第三版
想法：能不能用周为单位看进展，而不是按天
```

助手会判断该进哪个域、要不要问期限、是不是和已有记录重复。

### 三种形态

| 形态 | 用于 | 特点 |
|---|---|---|
| `task` | 事务、销售、实施、助手 | 有 `status` 与期限，可标完成 |
| `project` | 创作 | 有阶段 `stage`（`构思`/`起草`/`修订`/`完成`/`搁置`），可带里程碑 |
| `stream` | 灵感、拜访 | 只追加不合并，不需要期限；被转成创作后会标注去向 |

**状态值一律用汉字**，且**由域声明**，不写死在代码里：

| 域 | 状态值 |
|---|---|
| 事务 | `待办` / `进行中` / `已完成` / `已放弃` |
| 销售 | `商机` → `跟踪` → `立项` → `报价` → `中标` / `未中标` |
| 实施 | `待启动` → `实施中` → `验收中` → `已验收` / `已终止` |
| 创作（阶段） | `构思` / `起草` / `修订` / `完成` / `搁置` |

> **早期版本用的英文**（`todo`/`doing`/`done`/`dropped`、`idea`/`drafting`/`revising`/`parked`）
> 仍然认得：读文件时自动归一化成汉字，写入时传旧英文值也会落成汉字。
> 想把这些历史文件本身也改成汉字，跑一次
> `node tools/migrate-status-cn.mjs`（先 dry-run 看清单，再加 `--write`，会自动备份）。

### 生命周期：不是所有域都有"完成"

形态决定**数据长什么样**，生命周期决定**能对它做什么**：

| `lifecycle` | 含义 | 有完成/改期吗 |
|---|---|---|
| `task`（默认） | 待办事项 | 有 |
| `journal` | 经验教训库 | **没有** |

助手域就是 `journal`：它记的是"踩过的坑 + 约束"，一条经验不是待办事项。

所以：

- 新建时不写 `status`，也不写 `deadline`——不会变成"永远未完成"的积压项；
- 正文骨架是 **现象 / 根因 / 约束**，不是"进度 0%"；
- 面板不给"标记完成""修改截止日期"按钮，勾选圆圈换成方形 `≡` 标记；
- 不参与待办、逾期、完成率；`stats.open` 只算真任务；
- 要补充后续，只能用「编辑」写进下一步或备注（会追加到时间轴）。

> 早期版本把助手域当普通 task，导致每条经验都带 `status: todo`、越积越多，
> 还把任务计数撑高。老文件里的 `status`/`deadline` **不会被改写**，
> 读的时候统一收敛成"经验"，文件保持原样。
> （这些历史文件里的 `status: todo` 也不会被状态迁移脚本碰——脚本只处理声明了
> `legacyValues` 且非 journal 的域。）

自定义域想做成经验库，在 `系统/域.json` 里加一行 `"lifecycle": "journal"` 即可。

### 期限是硬约束

工作与创作在没有期限时**拒绝落库**，返回 `need_deadline` 让助手先问你。

理由很直接：没有期限就无法在到期前提醒，这条记录等于永远不响。

确实不急时说一声"不急"，助手会标成无期限（`openEnded`），此时 7 天不动会按停滞提醒。

灵感不受此限制。

## 存储结构

一条记录就是一个 Markdown 文件，放在你的数据目录下：

```
工作/YYYY/MM/W-YYYY-NNN-标题.md
创作/C-YYYY-NNN-名称/项目.md
灵感/YYYY/YYYY-MM.md          ← 月度流水，一个月一个文件
助手/YYYY/MM/A-YYYY-NNN-标题.md
```

文件长这样：

```markdown
---
id: W-2026-004
title: 华北院软著协作申请
created: 2026-10-28
updated: 2026-10-28
status: 进行中
deadline: 2026-11-15
tags: [软著, 沟通]
---

# 华北院软著协作申请

## 当前状态

**状态**: 进行中
**进度**: 40%
**下一步**: 等对方回执

## 时间轴
- [2026-10-28 14:20] 进展
  > 对方说材料还差一份技术说明
- [2026-10-26 09:10] 创建
  > 华北院软著协助申请在11月中旬完成就行。

## 备注
```

### 三条记法约定

1. **原话一字不改**，只进时间轴，且只出现一次
2. 系统自己的解释、点评、`"有问题告诉我"` 之类，**一律不落盘**
3. 时间轴只认 `## 时间轴` 小节

这样你的文件既干净又忠于原始记录，用别的编辑器打开也不会被污染。

## 判重规则

工作与创作新建时自动判重，防止同一件事裂成几条。

判定看三样（中文按相邻二元组算）：

- **标题相似度** = Dice(本次标题, 已有标题)
- **标题覆盖率** = 命中数 / 已有标题长度
- **时间轴覆盖率** = 命中数 / 已有时间轴长度

三档结果：

| 结果 | 触发条件 | 你会看到 |
|---|---|---|
| 直接并入 | 标题很像（≥0.72） | 内容追加到已有条目的时间轴 |
| 提示确认 | 只是"像"（≥0.45） | 问你要并入还是另建 |
| 新建 | 都不满足 | 直接建一条新的 |

### 一个刻意的保守设计

**"标题不同、内容高度重合"不自动并入，而是提示确认。**

因为自动并入一旦判错，你的原话会被塞进别人的条目里，事后极难发现。多一次确认的成本远低于这个代价。

### 短标题不做自动合并

标题短于 **6 个字符**时，只提示、不自动合并——哪怕相似度算出来很高。

因为极短标题的二元组太少，相似度会虚高：「开发」「测试」「开会」这类标题几乎彼此相似，自动合并会把毫不相干的新事项吞掉。

灵感不做判重——灵感本来就该散着，只累加。

## 提醒

每天固定时间（默认 12:00）一条消息，说你当前最该处理的几件。

排序依据（同一件事只出现一次）：

| 优先级 | 含义 |
|---|---|
| 逾期 | 已过期限 |
| 今天到期 | 就是今天 |
| 剩两个工作日内 | 临期，按工作日算（会跳过周末与法定假日） |
| 停滞 | 工作 5 天 / 创作 10 天没动 |
| 沉睡 | 灵感 30 天没管 |

**助手域（经验教训库）不参与提醒。** 一条经验记下来是为了将来查阅，
不是等着被"处理掉"；按停滞报警会让几十条经验永久挂在待办里，提醒也就失去意义。

提醒只讲"该收哪件"，**不做回顾**——回顾交给报告。

## 报告

四类周期，**没有周报**。

| 周期 | type | key 举例 | 自动生成 |
|---|---|---|---|
| 月度 | `month` | `2026-10` | 每月最后一天 20:00 |
| 季度 | `quarter` | `2026-Q4` | 3/6/9/12 月最后一天 20:00 |
| 半年度 | `half` | `2026-H2` | 6 月末、12 月末 20:00 |
| 年度 | `year` | `2026` | 12 月末 20:00 |

### 规则

- 月末按**实际日历**判断。大小月、平年二月、闰年二月都正确（2027-02-28 与 2028-02-29 都是月末）。
- **到点就投递**，不受夜间窗口推迟。`reportWindow` 只描述后台空闲时段，不参与投递门禁。
- **错过不补**：计划时刻 DSH 没开着，之后启动不会自动补执行，只记一条 `missedReports` 并显示在面板上。要补就说「补一份 2026-09 月报」。
- **各域分开存**，不混域、不共用正文：`报告/<域名>/<月报|季报|半年报|年报>/<id>-<key>-<域名><类型>.md`
- 助手域默认不参与汇总。

### 两个口径，不混用

报告里有两类信息，来源不同：

- **本期历史回顾**：只统计报告期内**已存在**的事项。9 月报告不会引用 10 月才创建的事项。
- **当前风险附录**：生成时刻仍逾期/停滞的事项。独立命名并标注快照时间，**不计入本期统计**。

分开的原因是：前者是事实，后者是"此刻的状态"，混在一起会让统计失去意义。

### 事实由代码算

报告里的新增/完成/逾期/停滞/分布/同期对比/趋势/重点回顾，全部由代码计算并落成 `facts.json`；模型只负责把这些数字写成可读的解读。

所以数字不会由模型编。

## 会话绑定

每日提醒和报告**可以绑到不同会话**——报告是"要坐下来写一篇"的重活，很适合单独放一个会话。

| 你说 | 效果 |
|---|---|
| 「把报告绑到这里」 | 只改报告会话 |
| 「把提醒绑到这里」 | 只改提醒会话 |
| 「提醒和报告都绑到这里」 | 两者都改（默认） |

写操作（记一条、改一条、改作息）会自动把两个目标都绑到当前会话；只读操作（查询、提醒、报告）不会改绑，但检测到你在别的会话时会附一句提示。

绑定状态存在 `系统/状态.json`。绑定的会话失效时，退回文件投递。

## 作息

编辑 `系统/调度.json`，或让助手改（`secretary_schedule`）：

```json
{
  "timeZone": "Asia/Shanghai",
  "reminderAt": "12:00",
  "reportWindow": { "start": "20:00", "end": "06:00" },
  "monthlyAt": "20:00",
  "quarterlyAt": "20:00",
  "halfAt": "20:00",
  "yearlyAt": "20:00"
}
```

`reportWindow` 只是"后台空闲窗口"的描述，**不会**推迟报告生成。四类报告到达各自 `*At` 时刻就投递。

改完立即重排，不用重启。

## 数据在哪

默认 `%USERPROFILE%\.dsh\plugin-data\dsh-secretary`（设了 `DSH_HOME` 则用它）。

想换到 Obsidian 库，在插件行 `config.dataDir` 指定绝对路径：

```yaml
- insert:
    - id: secretary
      name: dsh-secretary
      config:
        dataDir: 'E:\笔记\秘书'
```

数据是纯 Markdown，没有数据库，可以直接用 Obsidian、VS Code、git 打开和版本控制。也没有任何上传行为。

## 加一个域

编辑 `系统/域.json`（与内置合并，同 id 覆盖）：

```json
{
  "domains": [
    {
      "id": "health",
      "name": "健康",
      "shape": "task",
      "dir": "健康",
      "fields": { "deadline": { "type": "date" } }
    }
  ]
}
```

`shape` 只能是 `task` / `project` / `stream`。

加域**不用改代码、不用改工具、不用改面板**——面板的域筛选、录入下拉都是从配置读的。

## 社区入口

面板顶栏会显示一个社区链接，地址来自 `系统/社区.json`：

```json
{
  "label": "GitHub 社区",
  "url": "https://github.com/你的用户名/仓库/discussions"
}
```

改完下次快照即生效，不用重启。没这个文件、或 `url` 不是 http(s)，入口就不显示。带账号密码的 URL 也会被拒。
