## 记录

四个域（工作/创作/灵感/助手）形态不同，记法都一样：**说一句话**。

```
下周三之前把方案发给张明
记一条：给客户的产品手册要改第三版
想法：能不能用周为单位看进展，而不是按天
```

助手会判断该进哪个域、要不要问期限、是不是和已有记录重复。

### 三种形态

| 形态 | 用于 | 特点 |
|---|---|---|
| `task` | 工作、助手 | 有 `status`（todo/doing/done/dropped）与期限，可标完成 |
| `project` | 创作 | 有阶段（`idea`/`drafting`/`revising`/`done`/`parked`），可带里程碑 |
| `stream` | 灵感 | 只追加不合并，不需要期限；被转成创作后会标注去向 |

### 期限是硬约束

工作与创作在没有期限时**拒绝落库**，返回 `need_deadline` 让助手先问你。

理由很直接：没有期限就无法在到期前提醒，这条记录等于永远不响。

确实不急时说一声"不急"，助手会标成无期限（`openEnded`），此时 7 天不动会按停滞提醒。

灵感不受此限制。

## 存储结构

一条记录就是一个 Markdown 文件，放在你的数据目录下：

```
工作/YYYY/MM/W-YYYY-NNN-标题.md
创作/C-YYYY-NNN-名称/项目.md
灵感/YYYY/YYYY-MM.md          ← 月度流水，一个月一个文件
助手/YYYY/MM/A-YYYY-NNN-标题.md
```

文件长这样：

```markdown
---
id: W-2026-004
title: 华北院软著协作申请
created: 2026-10-28
updated: 2026-10-28
status: doing
deadline: 2026-11-15
tags: [软著, 沟通]
---

# 华北院软著协作申请

## 当前状态

**进度**: 40%
**下一步**: 等对方回执

## 时间轴
- [2026-10-28 14:20] 进展
  > 对方说材料还差一份技术说明
- [2026-10-26 09:10] 创建
  > 华北院软著协助申请在11月中旬完成就行。

## 备注
```

### 三条记法约定

1. **原话一字不改**，只进时间轴，且只出现一次
2. 系统自己的解释、点评、`"有问题告诉我"` 之类，**一律不落盘**
3. 时间轴只认 `## 时间轴` 小节

这样你的文件既干净又忠于原始记录，用别的编辑器打开也不会被污染。

## 判重规则

工作与创作新建时自动判重，防止同一件事裂成几条。

判定看三样（中文按相邻二元组算）：

- **标题相似度** = Dice(本次标题, 已有标题)
- **标题覆盖率** = 命中数 / 已有标题长度
- **时间轴覆盖率** = 命中数 / 已有时间轴长度

三档结果：

| 结果 | 触发条件 | 你会看到 |
|---|---|---|
| 直接并入 | 标题很像（≥0.72） | 内容追加到已有条目的时间轴 |
| 提示确认 | 只是"像"（≥0.45） | 问你要并入还是另建 |
| 新建 | 都不满足 | 直接建一条新的 |

### 一个刻意的保守设计

**"标题不同、内容高度重合"不自动并入，而是提示确认。**

因为自动并入一旦判错，你的原话会被塞进别人的条目里，事后极难发现。多一次确认的成本远低于这个代价。

### 短标题不做自动合并

标题短于 **6 个字符**时，只提示、不自动合并——哪怕相似度算出来很高。

因为极短标题的二元组太少，相似度会虚高：「开发」「测试」「开会」这类标题几乎彼此相似，自动合并会把毫不相干的新事项吞掉。

灵感不做判重——灵感本来就该散着，只累加。

## 提醒

每天固定时间（默认 12:00）一条消息，说你当前最该处理的几件。

排序依据（同一件事只出现一次）：

| 优先级 | 含义 |
|---|---|
| 逾期 | 已过期限 |
| 今天到期 | 就是今天 |
| 剩两个工作日内 | 临期，按工作日算（会跳过周末与法定假日） |
| 停滞 | 工作 5 天 / 创作 10 天 / 助手 14 天没动 |
| 沉睡 | 灵感 30 天没管 |

提醒只讲"该收哪件"，**不做回顾**——回顾交给报告。

## 报告

四类周期，**没有周报**。

| 周期 | type | key 举例 | 自动生成 |
|---|---|---|---|
| 月度 | `month` | `2026-10` | 每月最后一天 20:00 |
| 季度 | `quarter` | `2026-Q4` | 3/6/9/12 月最后一天 20:00 |
| 半年度 | `half` | `2026-H2` | 6 月末、12 月末 20:00 |
| 年度 | `year` | `2026` | 12 月末 20:00 |

### 规则

- 月末按**实际日历**判断。大小月、平年二月、闰年二月都正确（2027-02-28 与 2028-02-29 都是月末）。
- **到点就投递**，不受夜间窗口推迟。`reportWindow` 只描述后台空闲时段，不参与投递门禁。
- **错过不补**：计划时刻 DSH 没开着，之后启动不会自动补执行，只记一条 `missedReports` 并显示在面板上。要补就说「补一份 2026-09 月报」。
- **各域分开存**，不混域、不共用正文：`报告/<域名>/<月报|季报|半年报|年报>/<id>-<key>-<域名><类型>.md`
- 助手域默认不参与汇总。

### 两个口径，不混用

报告里有两类信息，来源不同：

- **本期历史回顾**：只统计报告期内**已存在**的事项。9 月报告不会引用 10 月才创建的事项。
- **当前风险附录**：生成时刻仍逾期/停滞的事项。独立命名并标注快照时间，**不计入本期统计**。

分开的原因是：前者是事实，后者是"此刻的状态"，混在一起会让统计失去意义。

### 事实由代码算

报告里的新增/完成/逾期/停滞/分布/同期对比/趋势/重点回顾，全部由代码计算并落成 `facts.json`；模型只负责把这些数字写成可读的解读。

所以数字不会由模型编。

## 会话绑定

每日提醒和报告**可以绑到不同会话**——报告是"要坐下来写一篇"的重活，很适合单独放一个会话。

| 你说 | 效果 |
|---|---|
| 「把报告绑到这里」 | 只改报告会话 |
| 「把提醒绑到这里」 | 只改提醒会话 |
| 「提醒和报告都绑到这里」 | 两者都改（默认） |

写操作（记一条、改一条、改作息）会自动把两个目标都绑到当前会话；只读操作（查询、提醒、报告）不会改绑，但检测到你在别的会话时会附一句提示。

绑定状态存在 `系统/状态.json`。绑定的会话失效时，退回文件投递。

## 作息

编辑 `系统/调度.json`，或让助手改（`secretary_schedule`）：

```json
{
  "timeZone": "Asia/Shanghai",
  "reminderAt": "12:00",
  "reportWindow": { "start": "20:00", "end": "06:00" },
  "monthlyAt": "20:00",
  "quarterlyAt": "20:00",
  "halfAt": "20:00",
  "yearlyAt": "20:00"
}
```

`reportWindow` 只是"后台空闲窗口"的描述，**不会**推迟报告生成。四类报告到达各自 `*At` 时刻就投递。

改完立即重排，不用重启。

## 数据在哪

默认 `%USERPROFILE%\.dsh\plugin-data\dsh-secretary`（设了 `DSH_HOME` 则用它）。

想换到 Obsidian 库，在插件行 `config.dataDir` 指定绝对路径：

```yaml
- insert:
    - id: secretary
      name: dsh-secretary
      config:
        dataDir: 'E:\笔记\秘书'
```

数据是纯 Markdown，没有数据库，可以直接用 Obsidian、VS Code、git 打开和版本控制。也没有任何上传行为。

## 加一个域

编辑 `系统/域.json`（与内置合并，同 id 覆盖）：

```json
{
  "domains": [
    {
      "id": "health",
      "name": "健康",
      "shape": "task",
      "dir": "健康",
      "fields": { "deadline": { "type": "date" } }
    }
  ]
}
```

`shape` 只能是 `task` / `project` / `stream`。

加域**不用改代码、不用改工具、不用改面板**——面板的域筛选、录入下拉都是从配置读的。

## 社区入口

面板顶栏会显示一个社区链接，地址来自 `系统/社区.json`：

```json
{
  "label": "GitHub 社区",
  "url": "https://github.com/你的用户名/仓库/discussions"
}
```

改完下次快照即生效，不用重启。没这个文件、或 `url` 不是 http(s)，入口就不显示。带账号密码的 URL 也会被拒。
