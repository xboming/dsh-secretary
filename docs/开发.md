# 开发说明

面向改代码的人。日常使用见[使用说明](使用.md)。

## 目录结构

```

├── index.js            Host 半入口：装配工具/路由/调度/提示词，热重载的"代"管理

├── cordis.patch.yml    插件行声明
├── lib/
│   ├── reloadable.js   版本化模块加载（热重载的地基）
│   ├── secretary.js    核心：读全库 → 判定 → 快照/报告/写入
│   ├── store.js        文件存储：原子写、串行队列、mtime 并发校验
│   ├── entries.js      条目读写：frontmatter + 正文 + 时间轴

│   ├── domains.js      域定义解析（内置 + 系统/域.json 合并）
│   ├── judge.js        判定：判重、优先级、停滞、沉睡
│   ├── calendar.js     工作日/节假日/期限归整
│   ├── schedule.js     定时器：每日提醒 + 四类报告
│   ├── report.js       报告：事实计算与落盘
│   ├── stream.js       灵感流水的追加与解析

│   ├── tools.js        模型可见的工具定义
│   ├── http.js         本机 HTTP 接口（面板用）
│   ├── prompt.js       系统提示词片段
│   └── util.js         通用工具
└── docs/               本目录
```

## 数据流

```
你说的那句话
   ↓ tools.js（模型可见的 secretary_add 等）
secretary.js  addRecord()
   ↓ 判重（judge.js）→ 写入（entries.js → store.js）
   ↓
Markdown 文件（唯一真相）

面板读：http.js → secretary.js snapshot() → client.js 渲染
定时到：schedule.js → secretary.js reminders()/report() → 投递
```

**Markdown 是唯一真相，索引只是可重建的缓存。** 任何时候删掉中间产物都不会丢数据。

## 改了代码怎么生效

DSH 宿主对插件 JS 有**进程级 require 缓存**。本插件自己绕开了它，所以只有入口需要重启：

| 改了什么 | 怎么生效 |
|---|---|
| `lib/*.js` | `dev-reload.cmd hot`，不用重启 |
| `client.js` | 按 Ctrl+R 刷新页面 |
| `index.js` | 重启宿主 |
| `系统/*.json` | 立即生效 |

`client.js` 首行是 `window.__ModuleLoader__.load({...})`，是纯浏览器模块。宿主在 Node 里 import 它会直接 `window is not defined`，所以宿主从不 import 它——改它只需要刷新页面。

### 热重载怎么做到的

Node 的 ESM 缓存以**模块 URL** 为键。同 URL 再 import 拿到的永远是首次求值的实例，这就是改完代码必须重启的根因。

解法是给 URL 加 `?v=<版本>`——带不同 query 的 URL 在 ESM 里算不同模块，会重新求值。

**坑在于子模块不会自动继承。** 父模块带 `?v=2` 时，它的静态 `import './x.js'` 仍解析成不带 query 的 URL，于是子模块永远命中旧缓存。表现是"改动有时生效有时不生效"，比彻底不生效更难查。

所以 `lib/*.js` 的内部相对导入全部改成动态形式，并用 `rel()` 把当前模块的版本号往下传：

```js
// lib/reloadable.js
export function rel(spec, moduleUrl) {
  const version = new URL(moduleUrl).searchParams.get('v') ?? '';
  return version ? `${spec}?v=${version}` : spec;
}

// lib/secretary.js
const { rel } = await import(new URL('./reloadable.js', import.meta.url).href);
const { splitDocument } = await import(rel('./frontmatter.js', import.meta.url));
```

`POST /dsh-secretary/api/reload` 换一个新版本号重新 import 整棵 lib 树，再整套重建工具、路由、定时器、提示词。

### 重载顺序是先拆旧、再建新

反直觉，但有原因：工具用固定名字注册（`secretary_add` 等），旧代还挂着时注册同名工具会直接抛

```
tool "secretary_add" is already registered
```

整个重载就失败了。代价是拆与建之间有几毫秒没有工具和路由，比彻底失败划算。

新代建失败时会自动回滚重建，不会把插件留在没有工具的状态。

### 局限

- `index.js` 自身由宿主 import，改它仍需重启。
- 宿主的 `@deepseek-ai/dsh-hmr` 实测未能触发本插件的模块替换（配了 `root` 指向源码目录，改 lib/index/touch patch 均无反应）。原因未查明；本插件自己的 reload 接口不依赖它。

`set_bundle` 关-开、`remove_bundle` + `install_bundle` **都不会**让宿主重新 import 插件 JS——这些操作只改链接与 patch，模块注册表里的旧实例继续服务。

## HTTP 接口

面板只走这几条，前缀 `/dsh-secretary/api`：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/snapshot?doneLimit=8\|all` | 面板快照 |
| GET | `/search?q=&domain=&limit=` | 搜索标题与时间轴原话 |
| GET | `/health` | 健康检查（`loadableAt` 用于判断模块是否被重新求值） |
| POST | `/add` | 面板"快速记一笔"（`createSeparate: true` = 用户已确认独立新建，只跳过判重，不改其他字段） |
| POST | `/update` | 完成 / 改期 / 内联编辑 |
| POST | `/link` | 灵感转创作、记录互相关联 |
| POST | `/schedule` | 改作息 |
| POST | `/reload` | 开发用热重载 |

## 关键设计决定

### 判重要双向成立

早期的判重只看 `时间轴覆盖率 = 命中数 / 已有时间轴长度`。分母只看已有条目，于是**输入越长越容易被误并入**：一篇 311 个二元组的开发日志凭空覆盖一条 37 个二元组的无关记录到 27%，标题命中数为 0 仍被判为同一条。

同一问题还有第二面：`标题覆盖率` 的分子用了含正文的集合，导致正文写得越详细越容易"覆盖"别人的标题。

修法是并入必须**双向成立**：已有内容被解释，且本次输入也被解释。并加 `titleReverse` 硬约束（本次标题至少一半要被已有标题解释）。任一不满足就降级为提示确认，不静默并入。

代价是"标题不同、内容高度重合"不再自动并入——这是刻意的保守，见[使用说明](使用.md#一个刻意的保守设计)。

### 短标题只提示不合并

`minAutoMergeTitleLength: 6`。标题短于 6 字符时直接跳过自动并入分支，只保留提示档。

原因：极短标题的二元组太少，Dice 与覆盖率都会虚高。不做这层保护时，「开发」和「开发票」这类标题会被判成同一条。

阈值都在 `lib/judge.js` 的 `THRESHOLDS` 里，改一处即可。

### 存储的三条保证

1. **写入原子**：先写同目录临时文件再 rename，进程被杀不会留下半个 JSON
2. **写入串行**：单进程内一条队列，两个工具调用不会同时改同一批文件
3. **外部改动可见**：读的时候带 mtime，写之前比对；Obsidian 里改过就拒绝覆盖

临时文件名必须全局唯一——只靠 `Date.now()` 在同一毫秒内的并发写会撞名，在 Windows 上表现为 `rename` 拿到 `EPERM`。

### 读 JSON 要剥 BOM

PowerShell 的 `Set-Content -Encoding utf8`、Windows 记事本、部分编辑器另存都会写 U+FEFF，而 `JSON.parse` 遇 BOM 直接抛错。`readJson` 是 catch 后返回 fallback 的，于是表现为"文件明明在，配置却完全不生效"的静默失败。

`store.readJson` 里统一 `text.replace(/^\uFEFF/, '')`。

### HTTP 写保护

写操作同时要求：

1. 来源必须是回环地址
2. `Content-Type: application/json`（挡掉跨站表单的 `text/plain` 提交）
3. `Origin` 若存在，host 必须是本机回环
4. `Sec-Fetch-Site` 若存在，不能是 `cross-site`

仅回环地址不构成身份校验，本机其它进程/页面可借表单直接改写记录。

```bash

```

`render-harness.mjs` 生成的页面**完全自包含**，不连宿主、不读生产数据。产物在 `shots/`，已加入 `.gitignore`，可随时用 `render-harness + shots` 重建。

### 热重载

```bash
node verify-hot-reload.mjs http://127.0.0.1:<端口>
```

它会临时给 `lib/util.js` 的 `stamp()` 加一个标记、调 reload、确认 `/health` 的输出里带上了标记，然后还原文件。

**这是唯一能证明"子模块真的重新求值"的方式。** 只看接口返回 200 是不够的——那只证明 `http.js` 刷新了。

## 发布注意

`package.json` 的 `files` 白名单决定发布内容。`lib` 是**目录**不是文件，漏了它插件会在安装后崩掉。`check-package.cjs` 专门验这个。

`shots/`、`verify-hot-reload.mjs` 等开发脚本不要进发布包。
